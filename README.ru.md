## 🚀 Три шага до результата

**Что нужно beforehand**: Node.js 18+ и установленное расширение Claude Code в VSCode.

```bash
npx vscode-claude-code-status-dot
```

`Cmd+Shift+P` (Mac) / `Ctrl+Shift+P` (Win/Linux) → введите `Developer: Reload Window` → отправьте промпт в CC.

Иконка вкладки тут же станет 🟡 жёлтой, а когда CC закончит — позеленеет 🟢 и прилетит уведомление. **Ставится один раз, работает сразу, никакой настройки не требуется.**

> Конфиг понадобится только если захотите выключить уведомления или поменять звук — см. раздел [Конфигурация](#-конфигурация-опционально).

## 💬 Что вы получите

### 1. Четырёхсостояный индикатор на каждой вкладке

Иконка вкладки каждой сессии CC меняет цвет по состоянию — 🟡 выполняется / 🟢 завершено / 🔴 прерывание (быстрое мигание) / ⚪ простой. **Отображается и в верхней панели вкладок, и в боковой панели «Открытые редакторы» вверху слева** — обе синхронны. Запустили несколько сессий параллельно — одним взглядом видно, кто ещё работает, а кто уже закончил.

### 2. Агрегат из 4 огней внизу — общее состояние всех сессий сразу

В нижней строке состояния окна один общий блок: 4 цветных шара + цифры при них:

```
🟢 1   🟡 2   🔵 1   🔴 0
готово  работает  ждёт ввода  прервано
```

Открыты 3 сессии — одна выполняется, одна ждёт вашей авторизации, одна завершилась — внизу сразу `🟢1 🟡1 🔵1 🔴0`, без переключения вкладок. **Позиции 4 шаров жёстко зафиксированы: изменение цифр не сдвигает ряд** (цифры в строке состояния моноширинные). Когда счётчик по лампе = 0, шар гаснет в серый ⚪ (занимает место, но не светится); счётчик > 0 — шар горит цветом.

### 3. Уведомления о завершении / прерывании

Когда CC заканчивает раунд или его прибивает rate limit, всплывает **системное уведомление** — и на переднем плане, и в фоне:

- **macOS**: выпадает из правого верхнего угла, звук `Glass` по умолчанию, без кнопок, через несколько секунд исчезает сам
- **Windows / Linux**: тост VSCode в правом нижнем углу, тоже без кнопок, исчезает сам

Можно смело переключиться в браузер или другое окно — уведомление напомнит, что пора вернуться.

### 4. 🔵 Pending: CC ждёт вашего ввода — сразу видно

Когда CC просит **разрешение**, задаёт вопрос или вызывает elicit-input (сценарии «ждёт пользователя»), нижняя 🔵 лампа увеличивается. В этот момент reader уступает иконку вкладки под родную синюю точку CC (**не переопределяет её**), а нижняя строка состояния ведёт **независимый счётчик pending** — понятно, сколько сессий висит и ждёт вас.

### 5. Companion-самовосстановление: после обновления CC патч сам вернётся

CC периодически автообновляется и полностью сносит патч. **Начиная с v0.2.0** при установке через `npx` автоматически ставится **companion-расширение** во все определённые VSCode-семейства редакторы (включая Insiders / Cursor / Vscodium); при следующем запуске VSCode companion видит, что CC снёс патч, **сам перезапускает patcher и один раз предлагает `Reload Window`** — в большинстве случаев вы ничего не замечаете.

### 6. Персистентность: удаление исходников / очистка кеша / обновление CC не страшны

Рабочая копия лежит в `~/.claude/cc-status-dot/` (SVG-иконки + hook-скрипты + patcher). Все hook-команды и пути иконок ссылаются на этот **абсолютный путь**, а не на каталог проекта. Удалите исходный каталог, почистите кеш `npx`, CC автообновится (перезапишет только каталог расширения, не тронув `~/.claude/`) — пропатченное расширение продолжит работать как ни в чём не бывало.

### 7. Workflow в фоне не даёт ложного «зелёного»

Когда в фоне крутятся subagent / cron, главная сессия **остаётся жёлтой** (не рапортует о завершении ложно) — hook `Stop` доверяет только счётчику `background_tasks` из payload, без дрейфа. Зелёной вкладка станет только когда работа реально закончена.

### 8. Безопасность-заглушка (CC никогда не сломается)

Перед записью `extension.js` патчер прогоняет `node --check` по полному файлу (assertCompiles-страж: кривой IIFE просто не запишется), пишет через атомарный `.tmp` + rename, автоматически перепроставляет `INJECT_VERSION`. Даже если patcher ошибётся — **расширение CC не будет испорчено**.

### 9. Откат в один клик без побочных эффектов

`npx vscode-claude-code-status-dot --revert` полностью восстанавливает `extension.js` из `.bak`, хирургически убирает hooks, **сохраняя все ваши пользовательские данные**.

> ⚠️ **Честное заявление**: это **патч, а не отдельное расширение** — VSCode не даёт сторонним расширениям менять иконку webview-вкладки другого расширения, единственный рабочий путь — пропатчить `extension.js` самого CC. Расплата: автообновление CC перезаписывает патч, но companion-расширение его восстанавливает (см. пункт 5).

## 🎨 Цвета состояний

| Цвет | Значение | Триггер |
|---|---|---|
| 🟡 Жёлтый `#CCA700` (**статичный**, без анимации) | Выполняется | Отправка промпта, до/после вызова инструмента (heartbeat), spawn subagent |
| 🟢 Зелёный `#3FB950` (статичный) | Раунд завершён | CC вызывает `Stop` (**через 5 минут автоматически сереет**) |
| 🔴 Красный `#F85149` (быстрое мигание) | Прервано / ошибка | CC вызывает `StopFailure` (rate limit, перегруз и т. п.) |
| ⚪ Серый `#808080` (статичный) | Простой | Начальное состояние / завершено более 5 минут назад / нет файла состояния |
| 🔵 Синий (родной CC) | Ждёт ввода пользователя (permission / question / elicit) | Родная синяя точка CC, **проект её не переопределяет**; в нижней строке состояния параллельно ведётся счётчик 🔵 pending |

> running — статическая жёлтая точка (без анимации); interrupted — быстрое мигание как аварийный сигнал. Полный контракт состояний (события / SVG / IPC / уведомления) — в [`docs/STATES.md`](docs/STATES.md).

## 🛠️ Подробно о возможностях

### 🟡 Четырёхсостояная точка иконки вкладки

Иконка вкладки каждой сессии CC меняет цвет по состоянию, **отображается и в верхней панели вкладок, и в виде «Открытые редакторы» вверху слева**. running/idle/done — статические точки, interrupted — быстрое мигание.

### 📊 Агрегат из 4 огней в нижней строке состояния

В нижней строке состояния (левая половина, ближе к центру) располагается **единый блок** (один `StatusBarItem` + текст через `parts.join(' ')`), внутри которого 4 индикатора идут в фиксированном порядке, разделённые небольшим пробелом: **🟢 done · 🟡 running · 🔵 pending · 🔴 interrupted**, за каждым шаром сразу следует число (предел 0/1/2/3/N, где N=4+):

- количество = 0 → серый шар ⚪ + притушенное число (лампа не горит, но занимает место)
- количество > 0 → цветной шар + светящееся число

**Позиции 4 шаров жёстко фиксированы — изменение чисел не сдвигает ряд**: VSCode применяет к каждому элементу строки состояния CSS-правило `font-variant-numeric: tabular-nums`, ASCII-цифры 0-9 одинаковой ширины в любом шрифте, независимо от рендеринга emoji.

🔵 (pending) имеет **отдельный счётчик, не связанный с `state`**: writer пишет флаг pending из хука `Notification` (permission/question/elicit), reader считает его независимо — поэтому даже когда вкладка уступает место родной синей точке CC, нижняя строка состояния продолжает показывать счётчик ожидания.

Три уровня garbage collection возвращают зависшие сессии в idle: `done` старше >5 минут → idle (зелёный −1); `running` без обновления mtime >30 минут → idle (крашнутая сессия); `interrupted` без обновления mtime >24 часов → idle. Pending GC на основе поля `st` (крашнутый pending → idle, минус жёлтый и минус синий).

Реализация — один рантайм `StatusBarItem` + текст через `parts.join(' ')` (IIFE каждые 500 мс мутирует `text` напрямую; без патча `package.json` CC, без блока `ThemeColor`).

### 🔔 Уведомления о завершении / прерывании

При переходе сессии в `done` или `interrupted` (только в момент самого перехода, без повторов):

- **macOS**: показывается системное уведомление (выпадает из правого верхнего угла, со звуком `Glass` по умолчанию, без кнопок, через несколько секунд исчезает само) — **и на переднем, и на фоновом плане** (`ccStatusDot.notifyWhenFocused` по умолчанию `true`);
- **Windows / Linux**: без `osascript` откатывается до встроенного сообщения VSCode (правый нижний угол, тоже без кнопок, исчезает само).

Звук задаётся параметром `ccStatusDot.notifySound` (по умолчанию `Glass`, общий для done и прерывания; `""` — без звука; можно поставить Basso/Ping/Hero и т. п.). При первом системном уведомлении macOS один раз спросит разрешение «Script Editor хочет отправлять уведомления» — разрешите.

### 🛡️ Companion-расширение самовосстановления (v0.2.0+)

При запуске `npx` патчер определяет каждый CLI семейства VSCode на PATH (`code`, `code-insiders`, `cursor`, `codium`) и ставит в каждый **companion-.vsix** (`cc-status-dot-companion`) через `code --install-extension`; одновременно копирует `patch.js` в `INSTALL_DIR/patch.js`.

При каждом старте VSCode companion-расширение проверяет маркер `cc-status-dot-injected` в расширении CC — если CC автообновился и снёс патч (маркер пропал), companion автоматически запускает `node ~/.claude/cc-status-dot/patch.js` и предлагает один клик `Reload Window`. Пользователь **ничего не делает руками** — восстановление происходит само.

### ⚙️ Во время workflow держится running

В фоне крутятся workflow / subagent — главная сессия остаётся жёлтой (без ложного «зелёного»), не сообщает о завершении ошибочно — `Stop` доверяет только счётчику `background_tasks` в payload, без дрейфа.

### 📂 Синхронизация Open Editors

В виде «Открытые редакторы» вверху слева вкладка CC **тоже несёт статус-точку**, полностью синхронно с верхней панелью вкладок.

### 🔒 Механизм персистентности

Пути SVG, на которые ссылается reader (внедрённый IIFE), и команды хуков, подключённые в `settings.json`, указывают на **абсолютный путь** `INSTALL_DIR` (`~/.claude/cc-status-dot/`), а не на каталог исходников проекта. При установке patcher идемпотентно копирует туда материалы из исходников (`resources/` + `hooks/`). Поэтому даже если:

- удалить каталог исходников проекта
- очистится кеш npx
- CC автообновится (перезапишет только каталог расширения, не трогая `~/.claude/`)

пропатченное расширение продолжит рендерить как обычно.

### ↩️ Откат в один клик без побочных эффектов

`--revert` полностью восстанавливает `extension.js` из `.bak`, хирургически убирает хуки, **сохраняет пользовательские данные**.

<details>
<summary>📖 Почему патч (а не отдельное расширение)</summary>

Иконка вкладки `WebviewPanel` VSCode (`iconPath`) **монопольно задаётся расширением, создавшим эту панель** — публичного API, позволяющего стороннему расширению менять её, нет. Session-вкладка CC — это WebviewPanel, созданный самим расширением CC, и её иконку можно установить только внутри `extension.js` CC. Все альтернативы (отдельное расширение, proposed API, перехват webview и т. п.) оказались недоступны — единственный рабочий путь это патч. Расплата: автообновление CC перезапишет патч, но companion-расширение (v0.2.0+) восстанавливает его автоматически.

</details>

## ⚙️ Конфигурация (опционально)

Добавьте в `settings.json` VSCode (если не настраивать — используются значения по умолчанию):

```json
{
  "ccStatusDot.notify": true,
  "ccStatusDot.notifyWhenFocused": true,
  "ccStatusDot.notifySound": "Glass"
}
```

| Параметр | По умолч. | Описание |
|---|---|---|
| `ccStatusDot.notify` | `true` | Общий переключатель уведомлений |
| `ccStatusDot.notifyWhenFocused` | `true` | Показывать уведомления и когда VSCode на переднем плане (macOS системное / Win-Linux VSCode toast); если иконок достаточно — поставьте `false`, тогда уведомления только в фоне |
| `ccStatusDot.notifySound` | `"Glass"` | Звук системного уведомления macOS (общий для done и прерывания; `""` — без звука; возможны Basso/Ping/Hero и т. п.) |

## ❓ FAQ

**После обновления CC статус-точка не загорается?**
Автообновление CC полностью заменяет каталог расширения, пропатченный файл перезаписывается оригиналом. **Начиная с v0.2.0**: companion-расширение при старте VSCode проверяет маркер `cc-status-dot-injected` и, если CC снёс патч, автоматически перезапускает `node ~/.claude/cc-status-dot/patch.js` и предлагает `Reload Window` в один клик — в большинстве случаев вам ничего делать не нужно. Если companion не установлен или хотите починить вручную: перезапустите `npx vscode-claude-code-status-dot` (копия рантайма SVG/хуков лежит в `~/.claude/cc-status-dot/`, обновление CC её не трогает; удаление исходников тоже не влияет).

**Сразу после установки иконка не изменилась?**
Сначала `Developer: Reload Window`. Если не помогло, запустите `npx vscode-claude-code-status-dot --status`: `patched: no` — перезапустите; `baked RES ... (STALE)` — перезапустите для переписывания на месте; `hooks wired: no` — перезапустите; `missing SVGs` — перезапустите для дозаполнения.

**Апгрейд со старой версии (через git clone)?**
Просто перезапустите `npx vscode-claude-code-status-dot` — апгрейд старой версии обрабатывается автоматически, `--revert` перед переустановкой не нужен.

**Состояние застряло в running?**
Скорее всего вы прервали CC через Esc (CC не вызывает Stop/StopFailure, хука нет). Следующий промпт или штатное завершение поправят состояние сами.

**`npx` не подключается?**
Запасной вариант — глобальная установка:
```bash
npm i -g vscode-claude-code-status-dot
vscode-claude-code-status-dot        # после установки запустите команду напрямую
```

## ⚠️ Известные ограничения

- **Ручное прерывание через Esc не даёт хука**: CC не вызывает Stop/StopFailure ([#45289](https://github.com/anthropics/claude-code/issues/45289)/[#9516](https://github.com/anthropics/claude-code/issues/9516)), состояние зависнет в running до следующего промпта/Stop.
- **Автообновление CC перезаписывает патч**: пропатченный `extension.js` заменяется оригиналом → **начиная с v0.2.0 companion-расширение автоматически перезапускает patcher + предлагает reload** (см. FAQ); без companion — перезапустите команду вручную.
- **Хрупкость minified-anchor + безопасность**: патч опирается на две точные строки в коде CC, при дрейфе версий patcher сообщит "Anchor mismatch" и откажется писать. Дополнительно перед записью `extension.js` патчер прогоняет `node --check` по полному 2.6 МБ файлу (assertCompiles-страж: кривой IIFE не записывается), пишет через атомарный `.tmp` + rename, автоматически перепроставляет `INJECT_VERSION` — **CC никогда не будет испорчен**.
- **При полном закрытии VSCode уведомлений нет**: IIFE живёт в процессе extension host, при закрытии VSCode он не работает → без уведомлений.
- **Клик по системному уведомлению не переключает на вкладку**: у osascript нет click-callback, уведомление только напоминает, возврат в VSCode — по зелёной/красной точке вкладки.
- **SBI priority без права собственности**: блок в нижней строке состояния занимает `StatusBarAlignment.Left` с priority `-9996` (одна точка); у VSCode StatusBarItem API нет расширительного namespace/владения — другое расширение с тем же priority может отодвинуть наш блок в угол. **Архитектура с единым блоком из одного StatusBarItem устраняет класс отказов «строка разрезана внешним SBI»** (4 отдельных SBI могли бы быть разделены вставкой чужого элемента между лампами; единый блок гарантирует, что внешняя вставка может лечь только по бокам). В типичных сценариях не срабатывает; см. STATES.md §7.5.
- **Зависимость от emoji-стека шрифтов**: кружки в нижней строке — это emoji-глифы (🟢🟡🔵🔴⚪), полагающиеся на системный emoji-шрифт. На macOS (Apple Color Emoji), Windows 10+ (Segoe UI Emoji) и большинстве дистрибутивов Linux (Noto Color Emoji) отображаются цветными; на Win7 / в headless-Linux / на удалённых SSH без emoji-шрифтов могут стать чёрно-белыми или «тофу». Это осознанный компромисс (emoji-кружки визуально приятнее кросс-платформенных цветных квадратов).

## 🏗️ Принцип + документация

**Патчит `extension.js` CC (внедряет таймер, устанавливающий иконку вкладки) + 9 хуков CC пишут состояние + уведомления о завершении/прерывании.** Полная документация:

- [`docs/STATES.md`](docs/STATES.md) — **контракт состояний (единственный источник истины)**: четыре состояния / отображение событий / IPC / уведомления
- [`docs/DESIGN-injection.md`](docs/DESIGN-injection.md) — принцип внедрения иконки (anchor / IIFE / привязка SVG)
- [`docs/USAGE.md`](docs/USAGE.md) — руководство по использованию (установка / диагностика / откат)

> Этот проект модифицирует `extension.js` расширения CC (с резервной копией, `--revert` полностью восстанавливает), а также пишет в `~/.claude/settings.json` (при первом запуске делает резервную копию). Скрипты хуков спроектированы так, чтобы **никогда не блокировать и не прерывать CC** — любая ошибка тихо делает `exit(0)`. Подключено **9 хуков** (включая `Notification`, пишущий pending).
